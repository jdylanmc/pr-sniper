# Provider writes

Reference for every provider write PR Sniper can make (GitHub; Azure DevOps in [its section](#azure-devops)): comment publication, exit replies and resolutions, Approve and Merge. Reviews are always on; each write is a per-assignment opt-in grant. Agents never write; the native host does ([ADR-0010](adr/0010-native-mutation-owner-intent-before-effect.md), [ADR-0016](adr/0016-revision-safe-publication.md), [ADR-0017](adr/0017-opt-in-provider-actions.md)).

## Rules

- Intent persists before every provider write. Reconcile the original; never resend.
- Live mutation acceptance only on an explicitly authorized disposable PR with cleanup. Fixtures never claim a live pass.
- Failure origin comes from typed provenance, never message text.
- Publication failures stay on the PR with cause and next action, not a global banner. Host persistence/read/coordination failures keep infra provenance and raise a host warning.

## Comment publication

- Grant: **Publish Comment** on the assignment. Off: findings stay local; no wait state, no manual task. Retired global defaults and repository policy dropdowns have no authority.
- Flow: host freezes validated output → maps findings to verified diff lines → one pending review with explicit commit SHA → submit `COMMENT`.
- Out-of-diff findings stay local. Review body = publication marker + `🔫 PR Sniper automated review` only: no summary, count, restated finding or CI status (**Status chatter**, [CONTEXT](../CONTEXT.md)). Custom Agent signature is not applied to the review body.
- One review per revision: once an assignment published findings on a head, later passes on that head refuse `new_comments` until a new head or explicit **Review again**. Replies only answer a comment addressed to PR Sniper, accept an author's won't-fix, or correct a mistaken resolution.
- Before and after mutation recheck: account/repo identity, head, reviewed target base, open and non-draft, eligibility, monitoring scope, publication permission. Disabling Comment or a gate change stops the attempt.
- **Withdraw publication**: revokes the attempt; removes only the exact owned pending batch when verifiable. Never touches another pending review. A confirmed visible batch is not undone.
- Stale: head change queues a new check only if eligible. Change after a visible submission keeps the receipt marked **stale after publication**. Base move without a new head: explicit **Review again**. A new local review cannot bypass a pending, uncertain or published batch for the same revision + assignment.
- Ledger `state/publications.json` (private): immutable output, mutation intent, pending-review identity, confirmed receipts, retry budgets. Restart reconciles the whole remote review and inline comment set (identity, exact content) before repeating. A missing receipt after an uncertain create never allows another create. Another pending review of the signed-in account is never submitted or deleted.
- Pending comments may have null line/side. New batches keep a verified diff position per finding. Reconcile checks position, path, body, original commit, author, review identity, comment count. Older batches: read-only comparison of frozen revisions; missing or truncated patch stops verification.
- Unusable batch (owned pending review whose inline comments differ from the frozen batch, changed lens, withdrawn): the exact owned pending review is deleted and the publication is **discarded**; no replacement batch, no Needs attention row. No automatic re-review; packet toss/re-queue handles a moved state. A submitted review with differing comments stays the receipt. Transient failures auto-resume on the review cooldowns; startup re-observes publications parked by older builds once.
- Unobserved effect (in-flight write, or read-back not yet consistent) = pending verification while the retry budget is live: Awaiting publication, no Failed, no notice, no status chatter. Failed (`Publish unconfirmed`) only once the operation parks.
- Retry: 3 retries within 15 min, shared. Operation and deadline survive restart. Rejection, config and permission failures need a fix. **Reconcile / retry publication** = fresh budget, same identity and uncertainty. After GitHub-confirmed submission with failed final eligibility, the receipt is kept and retry only reconciles.

## Conversation follow-ups (legacy, retired)

- Removed with the legacy path ([ADR-0021](adr/0021-review-packet.md)). The review packet reads comments; `leave_comments` replies (below).
- No Reply or Mention follow-up is admitted. Scans still record cursors, closures and owned feedback (`state/feedback.json`).
- Old `state/follow-ups.json` loads. Unanalyzed records: cancelled on startup (`Legacy follow-up retired.`). Analyzed replies: **Publish reply** / **Reconcile / retry reply** still drain; never re-POST an uncertain reply.
- Feedback: only provider closure settles a GitHub thread; a packet exit may resolve own threads. Confirmed publication is immutable.

## Packet exits

- Packet-mode runs write only through their exit; the host applies it. Gates (`exits::gates::offered`) decide what is offered; the exit-time check re-reads the PR.
- `leave_comments.new_comments`: one auto-created publication via `Batch::prepare_exit` (same ledger, pending review, reconcile as above). No `body` field; a legacy stored `body` is never posted. Every line must map to the diff (checked at the exit call too). Needs Publish Comment.
- Content failure (typed `Tossed`: unmappable line, 422 on the review create) before any remote review: publication **discarded** (`failure: tossed`), never resumed, no Retry of the batch; the review is tossed (error +1), a fresh review is queued, park at 3 (Needs attention, Tossed). With replies, the exit write tosses instead. Transient failures keep the retry budget. Startup re-prepares batch-less Packet publications parked as `provider` by older builds, so typed provenance decides.
- `leave_comments.reply_comments`, `resolve_own_threads`: host-executed, ledger `exit_writes` in `state/feedback.json`. See **Replies and resolutions**. Needs Reply Comment (both).
- `ready_for_human`: no GitHub write. Local summary (`pr-state.json`), queue shows Ready for you. Consumed at run completion only if the PR state still equals the one read.
- Consume: successful exit sets Baseline from a fresh post-write snapshot (`exits::consume_after`); own writes never retrigger. Moved: Toss, error count +1, new attempt through the retry budget, park at 3. Failed, panicked or tossed runs never consume.
- `approve_pull_request`, `approve_and_merge`: host records a packet `FinalReview` (exit run = evidence, no findings), the action pump approves with the intent marker and signature as the review body (the agent's comment stays local), then merges. Effective grant = assignment grant AND the exit. Our approval already on the head (including one an earlier exit placed): success, no write, state consumed. Approve exit on a closed PR or unassigned/inactive scope: never adopted, never observed again. CI red or conflicts deny both; CI pending denies merge; unmet required reviews deny merge. Confirmed write consumes the state; rejected write tosses and re-queues (park at 3). Approval comment required. GitHub refuses self-approval; merge on own PRs needs Include self. Approve ignores others' threads and changes requested; merge does not.
- `panic_exit`: no write. Typed failure, parks at once, cooldown auto-resume.

## Replies and resolutions (packet exit)

- One exit = one ordered effect: **preflight** (read-only) → publication batch (`new_comments`) → replies → resolutions → confirmed. Publication is held until preflight passes (`exit_writes::holds_publication`).
- Preflight verifies every item or tosses the whole exit before any effect: head unchanged, thread exists, repliable root, resolutions owned. Nothing partial. Toss = error +1, re-queue (ADR 0007, park at 3).
- Ownership: root must verify against a saved publication proof (receipt, account, review, original commit, exact root body) of this PR. Others' threads: reply only. Already resolved own thread = done, no write.
- Intent saved before each effect (`Attempted`). Reply body frozen at preflight: agent text, marker `<!-- pr-sniper:reply:exit-<id>-<n> -->`, revision stamp, `🔫 PR Sniper automated review`. Reconcile reads the thread: marker present = done. Attempted and absent = **never re-POST**; retries read only, then park `Failed`.
- Resolve: GraphQL `resolveReviewThread` with `clientMutationId`; unconfirmed result re-reads the thread; idempotent retry.
- Failure after the first effect = `Failed` (needs human), never silent replay. Before it = `Tossed`.
- Revision stamp per comment: thread root `original_commit_id` mapped to a local iteration, else `unknown`.
- Not `FollowUp`: own ledger, same rules. Legacy analyzed replies still drain.
- Confirmed exit calls `exit_writes::consume_after` (integration point): consume and re-baseline once, so own writes never retrigger; an external change in the write window keeps the packet baseline and queues one review (see [polling](polling.md)).
- Waiting on its batch: re-check every 10 s, no attempt spent; the 15 min retry window still runs, then the exit is tossed. Batch parked, stopped, stale or discarded = exit tossed (nothing partial).
- Pump picks the due write with the oldest retry time; a waiting write never blocks others.

## Approve and Merge

- Primary only. **Approval** pill `off | Approve | & Merge` (Azure DevOps: `off | Approve`). State `state/actions.json`.
- Only a packet approve exit authorizes (Packet exits above). No separate final review run.
- A sign-off (`lgtm`) acts only on green current-head CI. Accepted while CI was pending, it is a **Parked LGTM**: same final, same gates, re-attempted on each action observation with the shared backoff, one effect in flight, reconcile before acting. Parking writes nothing; only the approve/merge is sent. Before its first effect, a changed state sequence, a new head or red CI revokes it (`The review context changed…`, `CI is red…`); no write is sent and a normal review follows.
- Legacy `FinalReview` records (no packet approval) load as history, authorize nothing; unfinished ones are cancelled on startup (`Legacy final review retired.`). Their effects still reconcile.
- Approve: one acting-account vote, pins `commit_id`. No self-approve on GitHub. Never replaces an existing vote. Reconcile needs exact signed body, actor, commit, review receipt.
- Merge needs: confirmed current-revision approval from an eligible reviewer; green current-head checks; satisfied reviews and rules; `CLEAN`; no unresolved threads (outdated too); no required or active merge queue; provider-selected enabled method. Pins `expectedHeadOid` and explicit method. Admin bypass is never queried or used. Absent, partial, unsupported or inaccessible evidence blocks.
- Provider limits (`src-tauri/src/github/actions.rs`): fail closed beyond 100 threads, 100 comments per thread, or 100 check contexts. No direct-merge fallback for hooks, unavailable merge rules, merge queue or missing green CI.
- Reconcile: up to 3 automatic observations in the original window, then **Reconcile original action** (one more read). A merge proven after a lost response is terminal with no PR Sniper attribution. Rejected, stale or cancelled actions are never replaced automatically.
- Evidence read failure stays visible after Approve/Merge is turned off. **Retry provider evidence** follows native pump eligibility; disabled with a reason when no work, in backoff, or paused.
- Handoff: a cleared, unmerged PR keeps the personal-review handoff, also after auto-approval. Merge needs no acknowledgement. Merged = terminal history. Notifications and queue details stay separate for clearance, approval/merge, unknown outcome, personal review.

## Azure DevOps

Same state machine, ledger, gates and once-per-revision rule through the provider interfaces (`azure_devops/read/session.rs`). Approve is a reviewer vote; never completes or auto-completes a PR.
