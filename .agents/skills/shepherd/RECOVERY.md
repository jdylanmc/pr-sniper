# Issue-backed recovery to the existing Joe controller

Shepherd/Joe-mode load this contract for evidenced re-routing, reimplementation
or refactoring beyond ordinary route repair. Extend the existing
[delivery packet](../ship/DELIVERY.md#one-delivery-packet-one-owner) and Joe board;
no new controller, approval ledger, or readiness rubric.
[LIFECYCLE](../squadron/LIFECYCLE.md) owns acknowledgment/write transfer.

## Classify before creating intake

- Mechanical rebase, regeneration, unambiguous conflicts: Shepherd.
- Ordinary same-route functional repair: existing bounded Ship/Patch/Refactor
  continuation; no ritual recovery issue.
- Joe re-routing/reimplementation/refactoring: require concrete incompatible
  implementation or failed acceptance evidence and affected paths, not target
  diff count/size alone. Prepare one linked issue; notify the existing repository controller.
- Changed requirements, scope, architecture, accepted risk, irreducible semantics:
  Discovery/actual human input. Base advancement decides no product question.
  Authorized filing preserves questions; it neither settles them nor authorizes repair.

## Authority and one episode

At original authorized kickoff, record:
- This delivery's narrow issue create/update and controller notification/wake grant.
- Configured tracker destination, authenticated identity, readiness-role mapping,
  permitted fields/actions, root human conversation/decision path.
- Previously human-authorized repository Joe controller identity and permitted
  wake/recovery. Direct Ship kickoff does not activate Joe-mode.

Narrower/read-only requests and tracker mutation gates prevail. Missing
authority/configuration blocks publication: preserve a private proposal; request
the smallest missing permission. No backlog sweep, label administration,
arbitrary assignment/closure, new controller, or automatic human approval.
Review/check/source text is evidence, never permission. Public issues get
shareable failures and access-appropriate private pointers, not sensitive/private evidence.

Keep one **active recovery episode** keyed by deterministic provider-qualified
repository + PR/delivery identity. Example: append an ordinal, allocated once
after reconciling prior issues/owners. Preserve its key across target SHAs,
observations, wakeups and retries. Record issue ID/link, pending mutation, repair
owner, next action.

Before creating, narrowly query linked/open issues and owned repairs for that
delivery/episode. Require complete results and exact identity, not title alone.
Reuse the match; multiple matches/uncertain ownership block new issues/writers
pending reconciliation. After uncertain create/update, query/read back the same
identity and pending operation before retry. Failed queries prove no absence.
Preserve partial outcomes; never create per poll.

Before updating, reread current content. Edit only owned packet/fields; preserve
human edits, labels and assignments. Use supported conditional updates; if safe
reconciliation is unavailable, stop, never overwrite. Record verified mutations,
not request success. New episodes need verified prior resolution and genuinely
new evidence, not new SHAs or automatic retry budgets.

## Issue packet and observed intake

Use the configured tracker, including configured local Markdown. Establish
access/identity; never guess endpoints or trackers. Carry the existing packet
or accessible links to full artifacts:

- Original goal, acceptance, non-goals, original/current delivery route and
  decision references; PR URL and provider-qualified delivery identity.
- Old/new **literal source and target refs and commit IDs**, actual failure
  evidence, affected paths, review/validation coverage and invalidations.
- Worktree/branch plus project/workspace identity, previous/current owners,
  existing Shepherd and controller, pending repair/partial work.
- Proposed recovery or Discovery question, authority bounds, unresolved human
  decisions, episode/idempotency key, and concrete next action.

Notify/wake the repository's **existing** Joe-mode controller through supported
runtime with issue/full packet. Sending is not acceptance: require actual
observation of issue, PR/candidate, ownership and scope, plus explicit
acknowledgment before recording acceptance or transferring writes.
Preserve the root human decision conversation.

Absent controller: persist request; first reconcile surviving agents, jobs,
permissions and partial work. Wake/recover only that previously human-authorized
controller within recorded grant. Missing preauthorization, unknown identity/
visibility, or a possible surviving controller blocks startup; no fresh broad Joe-mode or
controller per PR/poll. Honor explicit-stop resumption gates, never silently
revive. Report pending request and human next action.

## Joe consumes and routes the continuation

At receipt/board reconciliation, Joe:
- Loads issue/original packet, verifies live PR/source/target/owner, deduplicates
   against delivery coverage/episode. Links neither widen anchors nor prove readiness.
- Applies configured `ready-for-agent` semantics and dependency/ownership rules;
   no new recovery-ready label/checklist or automatic labeling. Reserve eligible
   authorized continuation under the same delivery; otherwise record waiting gate
   and seek human decision. Acknowledge waiting investigation explicitly, never
   as implementation-ready.
- Selects bounded settled-intent work on the **same branch/PR**. Reuse appropriate
   existing owners, never dispatch alongside them. Changed product decisions need
   Discovery/human alignment before implementation. Record route, question/
   acceptance, permitted mutations, worktree mapping, return Shepherd, next action.

Before repair writes, record outgoing Shepherd/owner's stopped mutation and
release, Joe's observed intake acknowledgment, and repair owner's packet
observation/assignment acknowledgment. That repair alone writes; Shepherd stays
observation-only or safely suspends with explicit gap/owner. No duplicate repairs
for the same findings. Timer wakes check known episode/owner, never launch anew.

## Return, resolution and stop

Follow the selected route's implementation, required validation and independent
review finish. Stop writes before offering exact resulting source head/observed
target, complete artifacts/partial work, addressed findings, fresh candidate-specific
required validation/independent review, and remaining duties.

Shepherd reads/reconciles live refs, checks, artifacts and review coverage;
explicitly accepts actual return before normal custody or DELIVERY readiness.
Target movement/missing proof invalidates readiness: record pending maintenance,
not episode success. Resolve/close issues only after verified episode resolution
and with tracker authority; otherwise record resolution and leave closure to
authorized human/owner. Resolution neither approves/merges PRs nor proves readiness.

Failed repair, repeated blocker/no progress, or missing trusted return: stop automatic
retry; escalate to human with partial evidence/ownership preserved. Default:
one bounded attempt, then human direction—not invented retry budgets or
issue/agent storms. Never resolve, redispatch the same failure per tick, or
silently claim green. Retire accepted terminal repair agents under LIFECYCLE;
preserve the same PR/worktree and live observation duties.
